# 일정관리 웹 서비스 설문 피드백 개선안

## 1. 조사 개요

- 응답 기간: 2026년 9월 29일~10월 4일
- 응답 수: 5명
- 분석 목적: 팀 내 활용도를 높이기 위해 반복되는 불편과 낮은 평가 항목을 찾고, 개선 순서를 제안한다.
- 해석 시 유의점: 표본이 5명으로 작아 평균 점수만으로 일반화하기 어렵다. 한 명의 상세 의견도 실제 사용 흐름에서 발생한 문제라면 개선 후보로 포함하되, 개발 전 사용 로그나 추가 인터뷰로 확인하는 것이 좋다.

## 2. 핵심 요약

현재 서비스는 **배우기 쉽고 가볍다**는 장점이 있지만, 실제 업무 흐름에 계속 사용할 이유가 충분하지 않다는 문제가 더 크다.

- 5명 중 4명(80%)이 서비스를 `가끔만 사용`한다고 답했다.
- 사용법이 어렵다는 응답은 적었다. 4명은 어려움이 `전혀 없음`, 1명은 `약간 있음`이라고 답했다.
- 따라서 낮은 활용도의 주원인은 학습 난이도보다 **일정 변경 시 반복 작업**, **업무 방식과 기능의 불일치**, **슬랙 등록 과정의 번거로움**, **일부 사용자의 성능 체감**에 가깝다.
- 기능별 평점은 칸반보드가 4.2점으로 가장 높고, 슬랙 자연어 일정 등록이 3.6점으로 가장 낮다.
- 디자인 만족도는 3.4점으로 전체 평가 항목 중 가장 낮다. 가로 스크롤, 여백, 투박한 인상에 대한 의견이 있었다.
- 라이트/다크 모드는 4.0점으로 비교적 만족도가 높아 우선순위가 낮다.

## 3. 정량 결과

### 사용 현황

| 항목                      |      결과 |
| ------------------------- | --------: |
| 매우 잘 활용 중           | 1명 (20%) |
| 가끔만 사용               | 4명 (80%) |

### 만족도 평균

모든 점수는 5점 만점이다.

| 평가 항목                 | 평균 | 해석                                           |
| ------------------------- | ---: | ---------------------------------------------- |
| 전체 디자인               |  3.4 | 가장 낮음. 레이아웃과 시각 완성도 개선 필요    |
| 라이트/다크 모드          |  4.0 | 전반적으로 양호                                |
| 칸반보드                  |  4.2 | 가장 높은 평가. 핵심 기능으로 유지·강화        |
| 캘린더                    |  4.0 | 양호하지만 사용자별 편차가 있음                |
| 슬랙 자연어 일정 등록     |  3.6 | 기능 항목 중 가장 낮음. 등록 방식 개선 필요    |
| 슬랙 리마인드·주간 리포트 |  4.0 | 기능 자체보다 일정 데이터 입력률의 영향을 받음 |
| 이전 도구 대비 만족도     |  3.8 | 대체로 긍정적이나 압도적인 우위는 아님         |

응답 분산도 확인할 필요가 있다. 캘린더와 슬랙 자연어 등록은 각각 2점부터 5점까지 평가가 갈렸다. 기능의 존재 여부보다 사용자별 업무 방식과 사용 경험 차이가 큰 영역으로 보인다.

## 4. 긍정적으로 평가된 점

- 처음 사용해도 이해하기 쉽고 러닝커브가 낮다.
- 기존 도구보다 가볍고 깔끔하다는 평가가 있다.
- 비용 절감과 필요한 기능을 직접 추가할 수 있다는 장점이 있다.
- 칸반보드 만족도가 4.2점으로 높아 핵심 작업 화면의 기본 방향은 유효하다.
- 라이트/다크 모드는 현재 수준을 유지해도 된다.

개선 과정에서 이 장점을 해치지 않는 것이 중요하다. 기능을 추가하더라도 화면과 입력 절차가 복잡해지지 않도록 해야 한다.

## 5. 개선 우선순위

### 1순위: 일정 변경과 스프린트 단위 관리의 부담 줄이기

#### 확인된 문제

- 일정이 자주 바뀌는 상황에서 수정 작업이 반복되어 사용이 귀찮아진다는 의견이 있었다.
- 칸반보드에서 월의 특정 주차만 볼 수 있어 스프린트 전체 일정을 파악하기 어렵다는 의견이 있었다.
- 디자인 업무처럼 Figma와 구두 피드백 중심으로 진행되는 직군은 현재 서비스에 다시 기록할 필요성을 느끼기 어렵다.

#### 제안

- 스프린트 전체 보기 또는 시작일~종료일 범위 보기를 제공한다.
- 여러 일정을 선택해 날짜, 주차, 스프린트를 한 번에 변경하는 일괄 편집을 지원한다.
- 드래그 앤 드롭으로 주차·상태·담당자를 빠르게 변경하고 즉시 되돌리기를 제공한다.
- 일정 복제, 다음 스프린트로 이월, 미완료 일정 일괄 이동을 제공한다.
- 사용자가 같은 내용을 다른 도구에 이중으로 입력하지 않도록 링크 첨부나 최소 입력 방식부터 검토한다.

#### 기대 효과와 확인 지표

- 일정 수정에 드는 클릭 수와 시간을 줄인다.
- `가끔만 사용` 사용자의 주간 재방문율을 높인다.
- 일정 생성 후 7일 이내 수정된 항목의 처리 시간, 일괄 이동 사용률, 스프린트 보기 사용률을 확인한다.

### 2순위: 슬랙 일정 등록을 자연어 암기 방식에서 안내형 입력으로 개선

#### 확인된 문제

- 자연어 등록 양식을 기억하고 텍스트로 나열해야 해 웹에서 직접 등록하는 편이 낫다는 의견이 있었다.
- 슬랙 자연어 일정 등록 평균은 3.6점으로 기능 항목 중 가장 낮다.
- 슬랙 연동을 가장 먼저 개선해 달라는 응답과 부가 기능 확대 요청이 있었다.

#### 제안

- 슬랙 단축 명령 또는 버튼을 누르면 제목, 담당자, 기간, 우선순위, 상태를 고르는 단계형 모달을 연다.
- 자연어 입력은 없애기보다 보조 수단으로 유지하고, 해석 결과를 등록 전에 확인·수정할 수 있게 한다.
- 자주 쓰는 예시와 자동완성, 최근 입력값을 제공한다.
- 등록 성공 메시지에 생성된 일정의 핵심 정보와 웹 바로가기, 수정 버튼을 넣는다.
- 리마인드와 주간 리포트 확대는 일정 등록률이 오른 뒤 진행한다. 입력 데이터가 부족하면 알림 품질도 함께 낮아진다.

#### 기대 효과와 확인 지표

- 슬랙 등록 시작 대비 완료율, 해석 실패율, 등록 후 즉시 수정률을 확인한다.
- 웹 등록과 슬랙 등록의 소요 시간과 이탈률을 비교한다.

### 3순위: 레이아웃과 반응형 완성도 개선

#### 확인된 문제

- 디자인 만족도는 3.4점으로 가장 낮았다.
- 애매한 가로 스크롤, 불필요한 배경 영역, 일관되지 않은 여백, 투박한 인상에 대한 의견이 있었다.
- 더 여유 있고 시원한 구성을 원하는 의견도 있었다.
- 개선 우선 항목으로 디자인을 언급한 응답은 3건이었다.

#### 제안

- 1920×1080을 포함한 주요 화면 폭에서 의도하지 않은 페이지 가로 스크롤을 제거한다.
- 보드 영역만 필요한 경우 내부 가로 스크롤을 사용하고, 헤더와 필터는 고정해 맥락을 유지한다.
- 주차 선택 영역의 배경과 컨테이너를 단순화하고 버튼의 선택 상태만 명확히 표현한다.
- 카드, 컬럼, 필터, 모달의 간격 규칙을 디자인 토큰으로 통일한다.
- 넓은 화면에서는 정보 밀도를 낮추고, 작은 화면에서는 필터를 접거나 별도 패널로 이동한다.
- 디자인 개편 전에 현재 핵심 흐름을 와이어프레임으로 비교해 직관성을 유지한다.

#### 기대 효과와 확인 지표

- 주요 해상도별 가로 오버플로 발생 여부를 자동 점검한다.
- 일정 찾기·등록·수정 과업의 완료 시간과 오클릭 수를 비교한다.

### 4순위: 체감 성능 측정과 병목 개선

#### 확인된 문제

- 느려서 사용 빈도가 낮아졌다는 응답과 성능 개선 요청이 있었다.
- 반대로 가볍고 빠르다는 평가도 있어 모든 사용자에게 동일한 문제는 아니다.

#### 제안

- 추측으로 전면 최적화하기보다 페이지별 실제 성능을 먼저 측정한다.
- 칸반 첫 표시 시간, 주차 이동 시간, 일정 저장 응답 시간, 슬랙 등록 응답 시간을 기록한다.
- 데이터가 많거나 네트워크가 느린 조건에서 별도로 재현한다.
- 로딩 상태와 낙관적 업데이트를 적용해 저장 대기 체감을 줄인다.
- 느린 쿼리, 불필요한 재조회, 큰 클라이언트 번들을 측정 결과에 따라 순서대로 개선한다.

#### 기대 효과와 확인 지표

- p50·p95 응답 시간과 Web Vitals를 배포 전후로 비교한다.
- 사용자별 편차가 크다면 기기, 네트워크, 데이터량 기준으로 원인을 나눈다.

### 5순위: 리마인드·리포트는 데이터 품질과 함께 개선

#### 확인된 문제

- 리마인드·주간 리포트의 평균은 4.0점이지만, 일정 등록 참여도가 낮아 실제 효용이 떨어진다는 의견이 있었다.

#### 제안

- 우선 일정 입력률을 높인 뒤 리포트 내용을 개선한다.
- 데이터가 부족한 팀에는 단순 현황 대신 미등록·미갱신 일정 안내를 제공한다.
- 팀별로 알림 주기와 항목을 선택하게 해 불필요한 알림을 줄인다.
- 주간 리포트에는 완료, 지연, 다음 주 이월, 담당자 미지정 등 바로 행동할 수 있는 정보만 넣는다.

## 6. 권장 실행 순서

### 단기: 1~2주

1. 주요 해상도에서 가로 스크롤과 여백 문제를 재현하고 수정한다.
2. 칸반·일정 저장·주차 이동의 성능 측정을 추가한다.
3. 슬랙 등록 과정의 단계별 이탈과 실패 원인을 기록한다.
4. 스프린트 보기와 일괄 일정 이동 요구를 상세 의견 작성자 중심으로 짧게 인터뷰한다.

### 중기: 3~6주

1. 슬랙 안내형 등록 모달과 등록 전 확인 화면을 구현한다.
2. 스프린트 기간 보기와 미완료 일정 이월 기능을 구현한다.
3. 칸반 레이아웃 간격과 반응형 규칙을 정리한다.
4. 측정된 병목 중 사용 빈도가 높은 흐름부터 개선한다.

### 이후

1. 입력률이 개선되면 리마인드와 주간 리포트를 고도화한다.
2. 역할별 사용 패턴을 확인해 개발·디자인 등 직군별로 필요한 연동을 검토한다.
3. 같은 질문으로 후속 설문을 진행해 디자인, 슬랙 등록, 이전 도구 대비 만족도의 변화를 비교한다.

## 7. 다음 설문에서 보완할 점

- 현재 설문에는 `이전 툴 대비 아쉬운 점은 무엇인가요?` 문항이 두 번 있어 응답 해석이 분산된다. 하나는 삭제하거나 `구체적인 개선 제안`처럼 목적을 구분한다.
- 사용 빈도를 `매일`, `주 2~3회`, `주 1회`, `월 1회 미만`처럼 측정 가능한 구간으로 바꾼다.
- 응답자의 직군과 주로 사용하는 기능을 익명 범위에서 추가하면 낮은 활용도의 맥락을 구분할 수 있다.
- 일정 등록·수정·조회·리포트 확인 등 핵심 과업별 만족도를 따로 묻는다.
- 빈 응답은 불만 없음과 구분되지 않으므로 `해당 없음`, `사용하지 않음`, `불편 없음` 선택지를 둔다.

## 8. 우선순위 판단 결론

가장 먼저 해결할 문제는 기능 수의 부족 자체보다 **업무가 바뀔 때 일정을 유지하는 비용**이다. 스프린트 단위 보기와 빠른 일괄 수정으로 핵심 사용성을 개선하고, 동시에 슬랙 등록을 안내형 입력으로 바꾸는 것이 좋다. UI 정리와 성능 개선은 범위를 크게 잡기보다 가로 스크롤과 측정된 병목부터 처리한다.

이 순서라면 현재 강점인 쉬운 사용법과 가벼운 경험을 유지하면서, `가끔만 사용`하는 팀원이 반복적으로 사용할 이유를 늘릴 수 있다.

## 9. 제품 결정 반영

2026년 10월 6일 논의에서 성능 개선은 후속 과제로 미루고 디자인 개선을 먼저 진행하기로 했다. 첫 단계는 운영·모바일·어드민·모니터링 프로젝트 탐색 구조, 실제 일정 데이터 기반 메인 대시보드, 하위 일정 진행률을 포함한 칸반 카드 개선이다.
